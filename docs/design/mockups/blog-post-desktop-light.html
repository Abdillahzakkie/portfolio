Building a double-entry ledger on TigerBeetle

GoTigerBeetlegRPC
◆ Part of the project Settleo Non-custodial P2P / OTC crypto-settlement platform. View project →

In Settleo, exactly one service is allowed to move money: the ledger. Every other service — the gateway, the indexer, the escrow orchestrator — describes an intent, but only the ledger records the debits and credits that make it real. That single-writer rule is the whole reason balances can be trusted.

Why double-entry, and why TigerBeetle

Double-entry accounting is old, boring, and exactly the property you want when funds are involved: every transfer touches two accounts and the sum is always conserved. TigerBeetle is a database built specifically for that shape — accounts and transfers as first-class primitives — so the ledger service is the sole writer to it and speaks gRPC to everyone else.

A transfer, then, is not an UPDATE against a balances table. It is a two-sided, all-or-nothing entry:

Go · ledger service// A settlement is one atomic double-entry transfer.
func (l *Ledger) Post(ctx context.Context, m Move) error {
    t := tigerbeetle.Transfer{
        DebitAccountID:  m.From,
        CreditAccountID: m.To,
        Amount:          m.Amount,
        Ledger:          m.Asset,
        Code:            CODE_SETTLEMENT,
    }
    return l.client.CreateTransfer(ctx, t) // conserved or rejected
}
ℹ
Note

The ledger never talks to a chain directly. The indexer confirms on-chain events and asks the ledger to credit — reorg-safely — so a rolled-back block can never leave a phantom balance.

Keeping the writer alone behind gRPC means the trust boundary is small enough to reason about. Reviewers only have to audit one service to answer the question that matters.

If more than one service can write to the ledger, you no longer have a ledger — you have a race.

Everything else in the platform is downstream of that discipline: the escrow orchestrator settles against the ledger, compliance reads from it, and the console reports on it. But none of them writes.
